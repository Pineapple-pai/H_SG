# 两舵两全底盘改造说明

## 1. 目标

当前工程的底盘控制链路默认是“四舵四驱”构型，也就是：

- 4 个主动舵轮模块
- 每个模块都有 1 个舵向电机
- 每个模块都有 1 个驱动电机

现在底盘改成“两舵两全”后，新的物理构型变为：

- 2 个主动舵轮模块
- 2 个无动力从动全向轮
- 两个主动舵轮与两个从动全向轮为对角线布置

这里的关键点不是“底盘还是四个支撑点”，而是：

- **只有 2 个主动模块参与解算和控制**
- **2 个从动全向轮只作为支撑点，不参与驱动和转向控制**

因此，代码上必须从“按 4 个主动舵轮写死”改为“只控制 2 个主动舵轮”。


## 2. 当前工程的默认假设

当前代码中，底盘控制从运动学到 PID，再到功率分配，基本都默认 4 个主动舵轮。

主要体现在以下文件：

- `Task/ChassisTask.cpp`
- `Task/ChassisTask.hpp`
- `APP/Variable.hpp`
- `APP/Variable.cpp`
- `Task/PowerTask.cpp`
- `Task/PowerTask.hpp`
- `Task/EvenTask.cpp`
- `Algorithm/ChassisCalculation/StringWheel.hpp`

这些地方都有大量如下特征：

- 数组固定为 `[4]`
- 循环固定为 `for (int i = 0; i < 4; i++)`
- 功率平均分配固定为 `1/4`
- 静态损耗平均分摊固定为 `k3 / 4.0f`

也就是说，当前代码默认：

- 4 路舵向电机
- 4 路驱动电机
- 4 路轮速目标
- 4 路舵角目标
- 4 路速度环和功率环

改成两舵两全后，这套默认假设不再成立。


## 3. 两舵两全构型的控制本质

### 3.1 哪些轮子参与控制

两舵两全底盘里：

- 主动舵轮：参与逆运动学、PID、CAN 输出、功率分配
- 无动力从动全向轮：不参与逆运动学输出，不参与 PID，不参与功率分配

从动全向轮只在机械上提供支撑和约束，不是控制对象。


### 3.2 顶层控制量是否保留

上层一般仍然保留：

- `vx`：底盘 X 向速度
- `vy`：底盘 Y 向速度
- `vw`：底盘角速度

也就是说，模式控制逻辑通常可以继续输出：

- 跟随模式输出 `vx, vy, vw`
- 键鼠模式输出 `vx, vy, vw`
- 小陀螺模式输出 `vx, vy, vw`

真正要改的是下层：

- 如何把 `vx, vy, vw` 解成 2 个主动舵轮的目标轮速和目标舵角


## 4. 推荐的坐标系定义

为了避免符号混乱，建议统一底盘坐标系：

- 底盘中心为原点
- 底盘前方为 `+X`
- 底盘左方为 `+Y`
- 逆时针旋转为 `+vw`
- 长度单位统一用米
- 角度内部统一用弧度

后续所有主动轮位置、解算公式、相位补偿，都以这套坐标系为准。


## 5. 两主动舵轮逆运动学

### 5.1 基本公式

对于位于 `(x_i, y_i)` 的第 `i` 个主动舵轮：

```cpp
vix = vx - vw * y_i;
viy = vy + vw * x_i;
```

则其目标轮速方向向量为 `(vix, viy)`。

目标轮速模长：

```cpp
target_speed_i = sqrtf(vix * vix + viy * viy);
```

目标舵角：

```cpp
target_angle_i = atan2f(viy, vix);
```

如果轮速需要转换成 RPM，可按轮半径换算：

```cpp
wheel_rpm = target_speed_i / wheel_radius * 60.0f / (2.0f * M_PI);
```


### 5.2 就近转位逻辑

为了避免舵向电机走远路，需要保留“就近转位”：

- 计算目标角与当前舵角的差值
- 若差值在 `[-pi/2, pi/2]` 内，则直接转过去
- 若差值超出该范围，则目标角加 `pi`
- 同时把目标轮速乘以 `-1`

这样舵轮会优先走最短路径。

这部分逻辑和四舵轮版本一致，可以继续使用。


### 5.3 低速保角

当轮速向量模长非常小的时候，建议：

- 舵角保持当前值
- 驱动轮目标速度置 0

例如：

```cpp
if (tmp_velocity_modulus < 0.05f)
{
    Motor_direction[i] = current_steer_angles[i];
    Motor_wheel[i] = 0.0f;
}
```

这样可以避免低速时舵角乱跳。


## 6. 对角线布置时的坐标填写

### 6.1 主动轮为左前 + 右后

若两个主动舵轮位于：

- 左前：`(+L, +W)`
- 右后：`(-L, -W)`

则：

```cpp
float wheel_x[2] = {+L, -L};
float wheel_y[2] = {+W, -W};
```

其中：

- `L` 为底盘中心到前后轮的距离
- `W` 为底盘中心到左右轮的距离

例如底盘长 440 mm，宽 360 mm：

```cpp
const float L = 0.220f;
const float W = 0.180f;
```

则：

```cpp
float wheel_x[2] = {+0.220f, -0.220f};
float wheel_y[2] = {+0.180f, -0.180f};
```


### 6.2 主动轮为右前 + 左后

若两个主动舵轮位于：

- 右前：`(+L, -W)`
- 左后：`(-L, +W)`

则：

```cpp
float wheel_x[2] = {+L, -L};
float wheel_y[2] = {-W, +W};
```


### 6.3 从动全向轮的位置

从动全向轮位置通常不参与逆运动学解算，但建议仍然在文档中记录清楚，因为它影响：

- 真实底盘稳定性
- 侧移效果
- 转向阻力
- 调参难度

如果后续要做更高精度建模或稳定性分析，从动轮位置仍然有参考价值。


## 7. `phase` 的含义与标定

### 7.1 `phase` 是什么

`phase` 是数学目标舵角到电机反馈角度的机械零位补偿。

逆运动学求出来的角度，是数学坐标系下的理想舵角：

```cpp
atan2f(viy, vix)
```

但实际电机编码器反馈往往不是：

- 轮子朝前时角度等于 0

因为安装时舵轮零位通常有偏差，所以需要额外补一个相位量：

```cpp
target_angle = atan2f(viy, vix) + phase[i];
```


### 7.2 `phase` 怎么标定

以某个主动舵轮为例：

1. 只看舵向，不给驱动。
2. 手动将轮子摆到“滚动方向正对底盘前方 `+X`”。
3. 读取当前舵向电机反馈角度 `theta_meas`。
4. 数学上此时轮子朝向为 `theta_math = 0`。
5. 则该轮的：

```cpp
phase = theta_meas - theta_math;
```

因为此时 `theta_math = 0`，所以：

```cpp
phase = theta_meas;
```


### 7.3 更一般的写法

若标定时轮子摆到任意已知数学方向，则：

```cpp
phase = 编码器实际角度 - 数学目标角
```

例如：

- 轮子朝左，对应数学角 `pi/2`
- 此时编码器读数为 `2.10 rad`

则：

```cpp
phase = 2.10f - 1.5708f;
```


### 7.4 标定建议

建议每个主动轮至少做两次确认：

- 轮子朝前 `+X`
- 轮子朝左 `+Y`

用来检查：

- 电机反馈角度方向是否正确
- 相位补偿是否正确
- 轮子朝向与数学角度正方向是否一致

如果发现轮子目标方向总是反着，问题可能不是 `phase`，而是：

- 编码器角度正负方向定义和代码不一致
- 电机安装方向和代码约定不一致
- 底盘坐标系定义和实际使用不一致


## 8. 推荐的代码改造策略

### 8.1 不建议直接硬改 String_IK

原来的 `String_IK` 是按 4 主动舵轮写的，特征很明显：

- 轮子数组固定 `[4]`
- 舵角数组固定 `[4]`
- 安装方位角固定 `[4]`
- 循环逻辑全部默认 `4`

如果在原类上硬删成 2 路，容易把四舵轮逻辑和两舵轮逻辑搅在一起，后续不好维护。

更好的方式是：

- 保留原 `String_IK`
- 新增 `DualSteerIK`
- 底盘任务中切换到 `DualSteerIK`


### 8.2 当前已新增 DualSteerIK

工程中已新增：

- `Algorithm/ChassisCalculation/DualSteerIK.hpp`

该文件用于两主动舵轮逆运动学，接口风格尽量保持和 `String_IK` 接近。


## 9. 控制链路修改思路

当前底盘控制链路大致是：

1. 上层模式生成 `vx, vy, vw`
2. `Wheel_UpData()` 做逆运动学
3. `Filtering()` 做驱动轮反馈滤波
4. `PID_Updata()` 做舵向环和驱动环
5. `CAN_Setting()` 做功率分配与控制量整理
6. `CAN_Send()` 发 CAN

对于两舵两全，应改为：

- 只对 **2 个主动舵轮** 走上述链路
- 从动全向轮不进入链路


## 10. 各文件具体修改建议

---

## 10.1 `Task/ChassisTask.cpp`

这是底盘控制最核心的文件。

### 需要改的点

#### 1. 主动轮参数定义

原来一般是：

```cpp
float Wheel_Azimuth[4] = {...};
float phase[4] = {...};
```

两舵两全建议改成：

```cpp
float wheel_x[2] = {...};
float wheel_y[2] = {...};
float phase[2] = {...};
```

并把 IK 对象改成：

```cpp
Alg::CalculationBase::DualSteerIK dualSteerIk(...);
```


#### 2. `Wheel_UpData()`

原功能：

- 读取 4 个舵向角反馈
- 调用 4 舵轮逆运动学
- 输出 4 路轮速和 4 路舵角

改造后应为：

- 只读取 2 个主动舵轮当前角度
- 调用 `DualSteerInvKinematics()`
- 只写 2 路目标速度和 2 路目标角度

示意：

```cpp
for (int i = 0; i < 2; i++)
{
    dualSteerIk.Set_current_steer_angles(current_angle[i], i);
}

dualSteerIk.DualSteerInvKinematics(vx, vy, vw, phase_cmd, speed_gain, rotate_gain);

for (int i = 0; i < 2; i++)
{
    tar_speed[i] = dualSteerIk.GetMotor_wheel(i);
    tar_angle[i] = dualSteerIk.GetMotor_direction(i);
}
```


#### 3. `Filtering()`

原来默认滤 4 个驱动轮反馈。

改造后：

- 只滤 2 个主动驱动轮反馈


#### 4. `PID_Updata()`

原来默认：

- 4 路舵向角度环
- 4 路舵向速度环
- 4 路驱动轮速度环

改造后：

- 2 路舵向角度环
- 2 路舵向速度环
- 2 路驱动轮速度环

从动全向轮没有电机，不进入 PID。


#### 5. `CAN_Setting()` 和 `CAN_Send()`

原来会给 4 路主动模块发控制量。

改造后应只给：

- 2 个舵向电机
- 2 个驱动电机

剩余不存在的电机不要再发控制量。

Class_Slope slope_speed[ACTIVE_STEER_COUNT];

这样以后改构型更清楚。

## 10.4 `Task/PowerTask.cpp` 和 `Task/PowerTask.hpp`

这是功率分配和 RLS 功率估计模块。

### 当前问题

当前代码里很多地方默认 4 路电机，例如：

- `for (int i = 0; i < 4; i++)`
- `k3 / 4.0f`
- `MAXPower * 0.25f`

这些在两舵两全里都不合理，因为实际主动电机数已经变成 2。


### 修改原则

将原来固定写死的 4 改成主动电机数量：

```cpp
active_count
```

例如：

```cpp
average_power = MAXPower / active_count;
single_static_loss = k3 / active_count;
```

并且：

- 舵向功率分配按 2 路舵向电机做
- 驱动功率分配按 2 路驱动电机做
- 从动全向轮不进入功率模型


### 推荐思路

在功率模块里增加统一常量：

```cpp
static constexpr int ACTIVE_DRIVE_COUNT = 2;
static constexpr int ACTIVE_STEER_COUNT = 2;
```

这样后续所有求和、平均、误差分配都统一按主动电机数处理。

## 10.5 `Task/EvenTask.cpp`

该文件里会做电机在线检测。

当前默认会检查：

- 4 个舵向电机
- 4 个驱动电机

改成两舵两全后，如果物理上只剩 2 舵 + 2 驱，而代码仍检查 4 路，就会导致：

- 多出来的 2 路永远判离线
- 蜂鸣器或告警逻辑误报

因此这里要改成：

- 只检查存在的 2 个舵向电机
- 只检查存在的 2 个驱动电机


## 11. 是否保留 `vy` 侧移能力

理论上，两主动舵轮只要舵角可任意转向，仍然可以对 `vx, vy, vw` 做解算。

但实际能否稳定实现高质量侧移，取决于：

- 从动全向轮阻力是否足够小
- 轮子安装是否精确
- 车体重心分布是否合理
- 主动轮抓地是否足够

如果从动全向轮机械阻力较大，实车上可能出现：

- 侧移不顺
- 自转阻力大
- 对角移动时发抖
- 跟随模式摆头

因此，虽然代码上仍可保留 `vy`，但实车未必能表现得像四舵轮一样顺滑。


## 12. 推荐调参顺序

改完结构后，不建议直接沿用原四舵轮参数。

建议按以下顺序调试：

### 第一步：只测舵向

- 关闭驱动轮输出
- 只看 2 个主动舵轮目标角是否正确
- 分别测试：
  - `vx > 0, vy = 0, vw = 0`
  - `vx = 0, vy > 0, vw = 0`
  - `vx = 0, vy = 0, vw > 0`

观察：

- 朝前命令时，轮子是否都朝前
- 朝左命令时，轮子是否都朝左
- 自转命令时，两轮是否朝切向方向


### 第二步：低速驱动

- 给很小的驱动轮输出
- 检查轮速方向是否和舵角匹配
- 检查最近转位逻辑是否正常


### 第三步：调舵向环

先调：

- 舵向角度环
- 舵向速度环

保证舵角响应稳定，不抖，不慢，不冲过头。


### 第四步：调驱动轮速度环

两舵两全的驱动力分配与四舵轮不同，建议：

- 驱动轮速度环 `kp` 先降低
- 加速度斜坡先放缓


### 第五步：调跟随和自转

建议先把：

- `vw` 相关参数降到原来的 50% 左右
- `vx/vy` 加减速斜率降低到原来的 50% 到 70%

因为：

- 主动驱动点减少
- 可用牵引力下降
- 旋转控制更容易摆头和打滑


## 13. 推荐的测试顺序

建议按照以下顺序进行测试：

1. 轮子朝向测试
2. 原地前进后退测试
3. 原地小角速度旋转测试
4. 小速度侧移测试
5. 斜向运动测试
6. 跟随模式测试
7. 小陀螺模式测试

每一步都应确认：

- 舵角方向是否正确
- 轮速正负是否正确
- 是否存在明显机械卡阻
- 是否存在控制方向反转


## 14. 当前最推荐的改法

对本工程，推荐的最清晰改法如下：

1. 保留现有上层模式逻辑不变，继续输出 `vx, vy, vw`
2. 使用 `DualSteerIK` 代替四舵轮 `String_IK`
3. 将底盘任务中所有“主动舵轮控制链”改为 2 路
4. 将全局变量、PID、滤波器改为 2 路或引入主动轮数量常量
5. 将功率分配中所有固定 4 路逻辑改为按主动轮数量处理
6. 将在线检测改为只检查实际存在的 2 舵 + 2 驱
7. 重新标定 `wheel_x`、`wheel_y`、`phase`
8. 重新调试舵向、驱动、跟随和旋转参数


## 15. 常见错误与排查

### 15.1 前进命令下轮子不朝前

优先检查：

- `phase` 是否标定正确
- 当前角反馈单位是否为弧度
- 舵角正方向是否和数学方向一致


### 15.2 自转方向反了

优先检查：

- `wheel_x` / `wheel_y` 的符号
- 底盘坐标系定义是否统一
- `vw` 正方向是否按逆时针定义


### 15.3 轮速方向经常反

优先检查：

- 最近转位逻辑是否正确
- 驱动电机正方向和舵角正方向是否匹配


### 15.4 侧移很差

优先检查：

- 从动全向轮是否真的是低阻全向
- 安装角度是否准确
- 底盘是否存在偏重
- 地面摩擦是否过大


### 15.5 明明代码正确但实车发抖

优先检查：

- 舵角 PID 是否过大
- 驱动轮速度环是否过大
- 加减速斜率是否过激
- 机械结构是否存在间隙或偏心
